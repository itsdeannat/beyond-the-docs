# About this project

This is a project where I built an entire ecosystem of developer tools:

* A CLI
* An API
* An SDK

I built them because I wanted to understand how they work. 

I've used CLIs, APIs, and SDKs before, and I document APIs at work. But I didn't understand how they were built. How do you actually build a CLI? What does into designing an API? How exactly do teams generate SDKs? I wanted to know.

## How it started

Last December, after building some AI agents to improve API documentation workflows, I thought, "What if there was a CLI tool that could validate and improve OAS files?"

That idea eventually became **SpecGate**, a Go-based CLI that enforces OpenAPI specification readiness. I'd never built a CLI before, so I had to learn Go and the Cobra CLI framework. 

Once SpecGate was working, I realized that I didn't have a real an OAS file to test it against. So I built a Django REST API for a fictionality photography platform called **Fstop**.

While building it, I started asking different questions: How do you avoid overly “chatty” APIs? How should resources be structured so they’re easy to use and easy to document?

Then came another question. While working on SpecGate, I was also using OpenAI’s SDK to make API calls to GPT-5. This made me curious about SDks themselves and whether I could create one for the Fstop API.

I learned that SDKs are generated from OpenAPI specs and used **Speakeasy** to auto-generate a Python SDK. 

And suddenly I had a full ecosystem: an API, an OAS file, a CLI that validates it, and an SDK generated from it.

## Why this matters (to me) 😁

As a technical writer, I spend most of my time focused on the documentation layer. That means thinking about what developers need to know, how to present information clearly, what's missing or confusing. But I don't usually have to understand how the systems were *built*. 

By building these tools myself, I had to think about everything *before* the documentation layer. I asked more questions, like:

* How do you design an API so it's easy to document? 
* What work goes into building an SDK? 
* How do you help developers seamlessly integrate their code with your platform? 
* What's the benefit of building a deterministic CLI versus an LLM-driven CLI? 
* What's the relationship between API docs and SDK docs? 
* How do you design good UX experiences for CLIs?

By building all three tools, I had to understand these things.

This project is my way of getting hands on experience with these tools so I can understand them better, and ultimately, write better documentation for them.
