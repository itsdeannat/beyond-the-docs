# Why I rebuilt SpecGate

I initially built a tool called SmartDoc using Python and Typer. It used OpenAI's GPT-5-mini model to analyze OpenAPI files and surface missing documentation. It worked, but I ran into a problem: the results weren't deterministic.

If a user ran SmartDoc multiple times on the same file, they'd get different results each time.

That inconsistency taught me something important: **developer tooling should be predictable and consistent.**

So I rebuilt the project as SpecGate in Go with deterministic rules instead. It was harder to built because I had to define the validation logic rather than delegating all the work to the LLM. Now developers get the same result each time, and I trust the output. 

This is why SpecGate uses hardcoded rules for most checks. The only place it uses an LLM is the `specgate advise` command.
