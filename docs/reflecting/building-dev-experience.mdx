# What building developer tools taught me about developer experience

I started Beyond the Docs because I wanted to understand what happens before documentation is written.

As a technical writer, I spend a lot of time thinking about what developers need to know, how information should be structured, and where users might get stuck. But I typically start my work after many of the major technical and design decisions have already been made. 

I may be involved in conversations about UX or documentation considerations, but I'm usually evaluating the experience created by those decisions rather than making the decisions themselves. The CLI's UX has already been designed. The API's structure has already been defined. The SDK has already been generated. 

Building an API, CLI, and SDK gave me the opportunity to explore those decisions firsthand.
